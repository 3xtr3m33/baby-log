# Дневник ухода

PWA для учёта кормлений, подгузников и сна. Общий журнал на семью: записи видят все, кто вошёл
по одному коду приглашения. Работает офлайн, ставится на телефон иконкой.

## Запуск

```bash
npm install
npm run dev      # разработка
npm run build    # сборка в dist/ (иконки генерируются автоматически)
npm run preview  # посмотреть собранную версию
```

Перед первым запуском впишите свои ключи в `.env.local`:

```
VITE_SUPABASE_URL=https://ваш-проект.supabase.co
VITE_SUPABASE_ANON_KEY=anon-public-ключ
```

Ключ `service_role` в приложение не попадает и попадать не должен.

## Публикация

Приложение живёт на GitHub Pages: **https://3xtr3m33.github.io/baby-log/**

Любой push в `main` пересобирает и выкладывает сайт (`.github/workflows/deploy.yml`).
Ключи для продакшен-сборки лежат в `.env.production` — там только publishable-ключ,
который и так уходит в браузер вместе с бандлом; данные закрывают вход по коду
приглашения и RLS-политики.

База путей — `/baby-log/` (задана в `vite.config.js`). Если репозиторий переименовать,
префикс надо поменять там же, иначе PWA и ассеты сломаются.

### Локальный режим

Сейчас на сайте включён `VITE_LOCAL_ONLY=1` (`.env.production`): вход по почте не спрашивается,
в сеть приложение не ходит, записи лежат в IndexedDB этого устройства. Так его можно открыть
и пользоваться, пока не поднят общий доступ.

Чтобы вернуть вход и синхронизацию между телефонами — поставить `VITE_LOCAL_ONLY=0` и запушить.
Код авторизации и синка не трогали, он оживает как был.

## Что внутри

- **Сегодня** — счётчики «сколько прошло», лента суток на 24 часа, три большие кнопки,
  прогноз следующего кормления и итоги с полуночи.
- **История** — все записи по дням с фильтром по типу, выгрузка в CSV и JSON.
- **Статистика** — 7/14/30 дней: сон, кормления и подгузники столбиками, средние
  за сутки, обычный перерыв между кормлениями.

Детали записи: сторона груди, объём смеси в мл, свободная заметка.

## Проверки

```bash
npm run check
```

`scripts/check-stats.mjs` считает контрольные сутки руками и сверяет с расчётами
(сон через полночь, незакрытый сон, медиана перерывов, выгрузка).
`scripts/check-render.mjs` прогоняет экраны через серверный рендер — ловит белый экран
до того, как он уедет на телефон. Оба скрипта гоняются в CI перед сборкой.

## Как устроено

- `src/lib/db.js` — локальная база (IndexedDB). Экран читает только отсюда, поэтому приложение
  открывается мгновенно и работает без сети.
- `src/lib/sync.js` — очередь отправки, подтягивание изменений, realtime-подписка.
  Действие пользователя пишется локально сразу, сеть догоняет потом.
- Удаление — это `deleted: true`, а не удаление строки: иначе оно не доедет на второй телефон.
- Конфликты решаются по `id`, выигрывает запись с бо́льшим `updated_at` (его ставит сервер).
  Исключение — записи, ещё стоящие в очереди отправки: их сервер не затирает.

## Схема базы

SQL для Supabase — в инструкции по развёртыванию (таблицы `families`, `members`, `events`,
функции `my_family`, `create_family`, `join_family`, RLS и `supabase_realtime`).
